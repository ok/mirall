Profile — the Account screen, regrouped and renamed

Proposal for screens/Account.tsx: drop the per-box section headings, group the status boxes into one stacked-row card (the Settings.tsx pattern), fold About in, and retitle the page Profile. Click the toggle to flip themes.

Proposal — nothing here is implemented yet

Baseline is origin/staging (v1.8.0), not main — v1.8.0 added the Activity Log (viewer + settings), the Network settings screen (transfer limits + relays), per-space download folders, and layout/ScreenRouter.tsx. Account is now four sections and the Settings hub is seven tiles.

Recreated from shipped code (structure, class strings, a11y attributes and verbatim locale copy): screens/Account.tsx:70-181, screens/Settings.tsx:18-27, screens/AboutSettings.tsx:56-125, screens/ActivityLogSettings.tsx:93-110, layout/PageHeader.tsx, layout/SectionHeading.tsx, primitives/IconButton.tsx, primitives/Avatar.tsx (silhouette fallback, xl = 80px), primitives/CopyButton.tsx and widgets/NetworkStatusIndicator.tsx. Strings are from locales/en/common.json at origin/staging.

Proposed delta: no new primitive and no new token — a regrouping plus a copy fix. The page is retitled Profile; section headings (SectionHeading, text-xl + mb-6) become the the same SectionHeading every settings sub-page uses (Notification settings' "General" and "Events") — and the first group loses its heading entirely, because the page title now says it; Security, Activity and Network merge into one rounded-xl overflow-hidden row group; About is folded in as a third group (Option A) or becomes one row that opens the existing screen (Option B). Copy with a dashed underline is proposed new locale text; everything else is the verbatim shipped string.

A second problem v1.8.0 created: the same word in two places

Account and Settings now each own half of two features, and both halves carry the same label. useAppNavigation.ts is explicit that this is deliberate — "the viewer hangs off Account and the config off Settings … a cross-link between them is a lateral jump, not a step in a history stack". The split is right; the naming is what confuses.

On AccountIn SettingsWhat differs

The proposal takes the cheap fix: on the renamed Profile page the rows are named for what they show (Connection, Activity Log with its event count), Settings keeps its config names untouched, and the group label (This device) frames all of it as status rather than preference. Renaming the page helps here too: "Profile ▸ Connection" and "Settings ▸ Network" can no longer be mistaken for each other the way "Account ▸ Network" and "Settings ▸ Network" can. No screen is moved between parents, so the back-stack comment above still holds.

Proposed — recommended

2 · Option A — one page titled Profile: the card · This device · App

The page is now called Profile — Mirall has no accounts (no sign-in, no server; the identity is a local key), the entry point is your avatar, and every locale already ships the word (settings.profile → Profil / Profil / Perfil / Profilo). The profile card follows the title directly with no heading, because a "Profile" heading under a page called Profile is the same word twice. The two groups below it keep the shipped SectionHeading — the same label Notification settings uses for "General" and "Events", so this screen reads like the rest of the settings family. The saving comes from removing headings, not from shrinking them: Security, Activity and Network stop being three lonely cards with three headings and become three rows under one. About is dissolved into an App group and its screen is deleted.

a11y The group headings are real <h2>s inside their <section>, so the heading outline stays well-formed (h1 → h2 ×2; the profile card is the h1's own content and needs no sub-heading) — only the visual weight drops. The renamed title must be carried through topnav.account / topnav.accountWithIssue (the avatar's accessible name) and a11y.screens.account, or the nav will announce "Account" for a screen that says "Profile". Every row keeps the name/role it has today: <button aria-label="…">, the external link keeps aria-label="Documentation (opens in browser)" + target="_blank" rel="noreferrer", and the Connection row's status dot keeps role="img" aria-label="Online". The identity row is plain text (no role, not focusable) exactly as it ships — it is information, not a control. It is also conditional, so the group renders two rows when getIdentityProtection() has not resolved.

Three details worth a decision. (1) Connection replaces the row title "Online": with the Network section heading gone the row needs a noun, and this is also what un-collides it from Settings ▸ Network. The state moves into the description, where the shipped connectivity.* string is reused verbatim. (2) The Activity row's description becomes the event count — activityLogSettings.openLogSummary, already shipped and already rendered on the Activity-Log settings screen, so no new string and no new IPC (audit:stats). (3) The rows carry no dividers, matching the Settings hub; if the static version and identity rows read as fused to the buttons around them, the shipped divide-y divide-surface-container-high/30 from StorageSettings.tsx / NetworkStatus.tsx is the token-legal fix.

Proposed — alternative

3 · Option B — About re-parented, not dissolved

Same regrouping and the same rename, but About stays its own screen and Profile links to it with a single row. The page fits without scrolling in a small window, and AboutSettings.tsx is not touched at all — only the tile moves from Settings to Profile. This is the cheaper change, and the right one if About is expected to grow (licences, credits, third-party notices).

Decisions taken

  • · The page is called "Profile", not "Account". Mirall has no accounts — no sign-in, no server-side identity, just a local key — so "Account" is a promise the rest of the app never makes. "Profile" is what the page is mostly made of, it matches the avatar entry point, and it is the only candidate that costs nothing to translate: every locale already ships it as settings.profile (Profil / Profil / Perfil / Profilo). Rejected alternatives: Status (the page's first act is editing your display name, which is not status, and the Connection row below it already is the status), Information (vague, and it collides head-on with About, which is Informazioni in Italian), and You (grounded in the shipped actorSelf string, but it becomes the page title "Du" in German and "Vous" in French).
  • · Standard SectionHeadings for the groups the title does not name. The Settings hub gets away with no heading because it has exactly one group. This page has three — the first is the page's own subject, so it takes none, and the other two use the same SectionHeading as every other settings sub-page (Notification settings' "General" / "Events"). An earlier revision used the smaller eyebrow label to buy another 48 px; it was dropped after seeing it next to Notification settings, because it made this one screen label its groups differently from the whole family for a saving the regrouping already delivers.
  • · "This device", not "Status". The group holds a live connection verdict, a fact about where the identity key is stored, and an on-device log — only the first is a status. All three are true of this device, which is also the wording the activity-log copy already uses ("Never leaves this device"). It also reads as the natural opposite of Settings, which is about choices.
  • · Nothing moves between this screen and Settings. The v1.8.0 split — viewer on Account, config in Settings — is deliberate and documented in useAppNavigation.ts. This proposal renames rows and regroups cards; it does not re-parent a screen, so every back target and the existing cross-links keep working.
  • · The Profile card keeps its shape. It is the one block on the page that holds a form, not a list — avatar, input, counter, conditional Save. Squeezing it into row anatomy would cost an interaction (view → edit) to save ~50 px.
  • · Connection stays a link to the diagnostics screen. NetworkStatus.tsx is ~370 lines of maskable, copyable fields (plus the relay counters added in v1.8.0); it does not belong inline. The row is the summary, the screen is the detail — as it works today.
  • · The identity row stays non-interactive. It is a statement of fact with no action behind it. It gets a title so it matches row anatomy, but no chevron and no focus stop — a chevron that opens nothing is a broken promise.
  • · About leaves Settings either way. Version, changelog, docs and feedback are not preferences. Options A and B differ only in whether it becomes rows or a row.

Rejected alternatives

  • · Rejected Merge the Activity-Log settings into Profile so there is one Activity destination. That undoes a deliberate v1.8.0 decision, mixes "what I chose" (retention, delete) into a status page, and would strand the activity-log-settings back target. Renaming the rows fixes the confusion for free.
  • · Rejected Fold the profile into the row group too (avatar + name as a display row that expands to an editor). Maximum compaction, but it invents an inline-edit pattern the app does not have anywhere else, and hides the primary action of the screen behind a click.
  • · Rejected Tabs or a segmented control (Profile / This device / App). Three tabs for three short groups is more chrome than the headings we are removing, and it hides content that currently costs one scroll.
  • · Rejected Merge everything into a single card with dividers. Profile-form and status-rows are different anatomies; one container would force the form to adopt row padding or the rows to adopt form padding.
  • · Rejected Move About to a top-level nav entry. TopNav is a drag region with three controls and no room; adding a fourth for the least-used screen inverts the priority.
  • · Rejected Inline the network diagnostics fields (peer count, NAT, DHT, relay counters) on Profile. They are already one click away and the anti-pattern rule applies: raw fields the user cannot act on do not belong on a profile page.

Open questions for the discussion

  • · A or B? Dissolve About into the page (one destination, longer scroll) or keep it as a screen behind one row (shorter page, one more click). A is recommended: About is a version string and four links — too little to justify a navigation node.
  • · "This device" or "Status"? "Status" is tighter and was the starting point; "This device" is the one that stays true once the activity log and (later) the recovery key are rows in it.
  • · Do the internal identifiers follow the rename? Recommendation: no. The screen id 'account', openAccount, preAccountScreen and Account.tsx are not user-visible, and renaming them touches ScreenRouter.tsx, useAppNavigation.ts, the a11y screen map and the keyboard commands — churn on the back-stack for no user-facing gain. Rename the five strings, leave the routing alone.
  • · Dividers between rows? No dividers matches the Settings hub; the divide-y divide-surface-container-high/30 already used in Storage and Network status would separate the static rows (version, identity) from the interactive ones more clearly.

Coverage this change would owe (.claude/testing.md)

  • · Frontend — the Profile screen renders all three groups; the Connection row navigates to network-status and the Activity row to activity-log; the identity row renders each of the three IdentityProtection values and is absent while unresolved; the Save button appears only when hasChanges; the version row shows the staged-update line when an update is pending; the Activity row shows the count from audit:stats and the recording-off state when audit.enabled is false.
  • · Frontend (navigation) — with About dissolved (Option A): the about.open command lands on the profile screen, the 'about' case is gone from ScreenRouter.tsx, back from network-status and activity-log still returns to it, and activity-log-settings still returns to Settings.
  • · Copy / i18n — the rename is five keys × five locales: account.title, account.intro, topnav.account, topnav.accountWithIssue, a11y.screens.account. Assert no locale still renders "Account"/"Konto"/"Compte"/"Cuenta" for this screen, and that the German stays in the Du-register the rest of the file uses.
  • · Accessibility — jsx-a11y clean, no new axe violations, heading order h1 → h2 preserved, the TopNav avatar's accessible name matches the new screen title (and its issue variant still announces the connection problem), every row targetable by name/role via agent-desktop, and a VoiceOver pass confirming the group labels still announce as headings.
  • · Not owed — no unit / integration / two-peer coverage: this is renderer layout and copy only, with no data-layer or P2P behaviour change. (audit:stats is an existing call, already used by the Activity-Log settings screen.)
