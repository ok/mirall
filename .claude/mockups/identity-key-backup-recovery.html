Architecture note (identity): the recovery file is wrapped/unwrapped inside the worker (it holds M and sodium's Argon2id). Only the passphrase (in) and ciphertext (out) cross the IPC boundary — M itself never leaves the worker, and is never shown on screen. Decisions locked: passphrase-encrypted file · MIR-36 included · warnings only (no biometric re-auth).

Architecture note (data): the Corestore backup is also a worker job — suspend() → incremental directory mirror (bare-fs) → resume(). The mirror copies only ciphertext: every local bee is encrypted at rest (MIR-40, the hard prerequisite), drives are SCK-encrypted (MIR-01), M is enveloped (MIR-02/24) — so the backup carries no archive password of its own. Decisions locked: raw incremental mirror · default off · cadence manual / daily / weekly / on-quit · gated behind a backup flag.

Two things to back up — and what a complete restore needs

Grounded in the recovery matrix (plan-mir-30-36 §12.1). The two backups are complementary; keep both for a one-step move to a new device.

Your recovery key (Group A · B)

The one thing that can't be rebuilt. Restores you as yourself — same network identity, contacts recognize you. A passphrase-encrypted .mirallkey file.

Your data folder (Group C · D)

Your spaces, profile, and the keys to spaces others shared with you. Brings everything back in one step. An encrypted incremental mirror of app-storage.

Complete restore (new device): restore the data folder, then add your recovery key. Data-only = no identity; key-only = identity but joined-space files stay unreadable. Group D shows both paths together.

a11y Progress is announced via the role="status" aria-live="polite" line (the bar is decorative, aria-hidden); failures use role="alert"; the transfer choice is a labeled role="group". Cadence + "Back up now" stay disabled until a destination exists. A missing destination fails the worker's assertWritable pre-flight → lastError surfaces here; the scheduler retries next tick.

Proposed new Why a transfer never blocks the backup: the worker copies the immutable bulk live and takes only a brief suspend() to finalize (two-pass). A write that lands during that window stalls then resumes — it never errors — and append-only logs capture an in-flight file up to its current blocks (it resumes from there). So manual backups run immediately (with the choice above), scheduled backups defer while a transfer is active (anti-starvation after one overdue interval), and on-quit just proceeds. Detail in plan-corestore-backup.md §2.5 (decisions D8 · D9).

Reading the mockup

  • · Four groups, one journey. A/B back up & restore your identity (recovery key, MIR-30/36); C/D back up & restore your data folder (Corestore backup). The spine panel up top and the D5 capstone show how the two combine into a complete restore.
  • · Recreated from shipped code: Account (with the new Data-backup section), Onboarding, and the locked screen. The four modals, the locked/restore screens, and the backup section's controls are proposed, assembled only from Modal, Button, Toggle, SegmentedControl, FilePath, DropZone styling, inputs, toast, and design.md tokens — no invented visual language.
  • · Primitives, faithfully: the Data-backup section is the real Toggle (role="switch"), SegmentedControl (role="group" + aria-pressed), FilePath (head-truncate + title), and primary Button — exact class strings copied from src/renderer. No new primitive was invented.
  • · Tokens only. Every colour resolves to a design.md token (surfaces step the surface-container-* ramp; danger lives in the error-container family; the warning glyph uses secondary; progress fills use primary). Annotation chrome (badges, captions, the state-card labels in C2) uses literal colour — that's mockup furniture, not app UI.
  • · Modal anatomy is faithful: px-10 pt-10 pb-6 header, px-10 pb-10 space-y-6 body, footer of two flex-1 h-14 buttons (secondary + primary/danger); panel rounded-3xl shadow-2xl shadow-black/30, opaque surface-container-lowest (blur lives on the backdrop, never the panel).
  • · No false assurance. Import shows file name + created date; restore shows folder name + created date + file count + a "Complete backup" check (all actionable from manifest.json) — never a raw key/store fingerprint to "verify."
  • · Security shape: M never appears on screen. The data backup copies only ciphertext (MIR-40 encrypts local bees at rest; that's the hard prerequisite) — so the backup itself carries no archive password, and the section never displays anything secret.
  • · No modal for backup: Group C is inline Account config (Toggle/folder/cadence/Back-up-now); Group D is a modal flow because restore is destructive and relaunches. Failures surface as role="alert"; progress + status as role="status" aria-live="polite".
  • · Transfers never block the backup (C2 d/e): the engine copies the bulk live and suspends only briefly to finalize, so an in-flight transfer just keeps running and is captured up to that point. Manual "Back up now" runs immediately and offers a "wait" choice; scheduled runs defer politely while a transfer is active. The indicator + policy come straight from the plan's D8/D9.
  • · Copy status: reused strings are verbatim from locales/en/common.json (Account/Onboarding/Storage/actions). All backup/recovery wording is Proposed new and needs real common.json keys (settings.backup*, recovery.*; + German, generic masculine, informal du) at implementation.
  • · Light + dark: the "Toggle dark" button flips .dark on the root for every frame at once.
