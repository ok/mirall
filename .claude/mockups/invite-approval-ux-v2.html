The two-step flow

Configure → Create → copy → close. The link doesn't exist until the choices are made, so you can never copy the "wrong" code.

What changed vs today

  • One link. The Code / App-link format selector is gone. We emit the mirall://join/<code> app link only — the Join dialog's extractInviteCode() already peels that back to the bare code, so a single link works for everyone. No need to explain "code vs link."
  • Auto-approve stays — the same shipped Toggle, now part of the choices you make before the link exists.
  • Expiry, not headcount. Three presets (2 hours / 2 days / 2 weeks); no per-person limit. Every link expires — a real security win, since today's invites never do.
  • Create-then-copy. The link is revealed only after Create invite link, so the choices are locked in first. This kills the original bug: you can no longer copy a non-auto code before flipping the toggle.
  • Confirmation. The Created step shows the settings back as badges (Badge) + a plain-language note, so what you share is unambiguous. Change returns to step 1; Done closes.

Backend note (honest about feasibility)

This unifies today's split model into one per-link record: { inviteId, expiresAt, autoApprove }, baked into the link and persisted (generalizing today's single-use auto-admit/{spaceId}/{inviteId} nonce, space.js:562). On a join request, onJoinRequest (worker/main.js:260) looks it up: expired → ignore; autoApprove → grant; else → manual request banner. Reusable until expiry (no per-person consume/delete). Two real changes: (1) the nonce is no longer single-use, and (2) expiry now also gates review links — which today have no per-link record at all, so this is what makes "every link expires" possible.

Accessibility

  • Auto-approve is the real Toggle (role="switch" + aria-checked, label + description).
  • Expiry presets follow the shipped segmented pattern: a role="group" labelled by "Link expires after", buttons carrying aria-pressed. The selected preset reads its pressed state to AT.
  • Create / Copy / Change / Done are real buttons with visible focus rings; Copy keeps its content_copy → check swap on success.
  • The settings badges are decorative summaries of state already conveyed in text — the note ("joins instantly until Sun, 29 Jun") carries the meaning, so the badges add no AT-only burden.
