Organization page: managed settings — mockup

Replaces the “What the organization sees” paragraph with a list of what the organization manages on this computer, one row per settings page it locks, each showing the locked values and leading to that page. Baseline: origin/main @ 418e0c91 plus the instance-reporting branch (revoked notice).

Recreated from code reproduced from the shipped .tsx Proposed new built from existing primitives and design.md tokens a11y name / role / state intent

Anatomy. A SectionHeading “Managed settings” over a ROW_GROUP of ActionRows, the same vocabulary as Settings. Each row: the settings page’s own Tile icon and name (SettingsScreen.tsx: hub Network, history Activity Log, shield Backup), then one line per locked value, each led by the lock glyph that ManagedNote uses (16px, text-secondary). The chevron opens that settings page, where each locked control already says “Set by Acme Test GmbH”.

Values use the controls’ own labels: networkSettings.relays.useRelay, .alwaysLabel, activityLogSettings.recordActivity, .retention + retentionDays, backup.autoLabel, backup.folderTitle. Only the heading is new copy. A page with no locked key has no row; the section is absent when nothing is locked.

Not shown: what the organization sees. It lives in the privacy policy (U-3, amended 2026-10-20).
