Owned folders — mockup

Active design. Single-writer folder shares, browse-only by default, opt-in read-only mirror. Click the toggle to flip themes.

Active design

This mockup illustrates the "owned folders" approach. Each folder has one owner; the owner pushes from their local disk to the space; everyone else sees the folder as read-only (browse-only by default, optional local mirror).

2 · Mount this space

The space mount is a configuration anchor — it gates the "Add folder" action and serves as the default parent location for folders you create or mirror. It doesn't watch or sync anything on its own. Deliberately simple: one field, no direction picker.

Heads-up: the space itself doesn't sync. Each folder you add will sync individually — your own folders push to the space, and other peers' folders only appear here if you mirror them.

5 · Mirror a foreign folder

Triggered when a peer clicks "Mirror to disk…" on a browse-only foreign folder. Lets them pick a local location for the read-only mirror. Default: a subdirectory under the space mount, with the owner's name suffixed so two same-named folders from different owners don't collide on disk.

Reading this mockup

  • · Two layers. Layer 1 — loose file sharing — works the moment a space exists (drop a file, others download to ~/Downloads/). Layer 2 — owned folders — is opt-in via the space-mount ceremony. Layer 1 keeps working whether or not the space is mounted.
  • · Owned folders. Each folder has exactly one writer: the peer who created it. The owner picks any location on disk; chokidar watches; changes flow continuously from their disk to the space.
  • · Foreign folders are browse-only by default. They appear in the UI with the owner's avatar. Individual files are downloadable on demand to ~/Downloads/, identical to today's single-file shares.
  • · Mirror to disk is opt-in per foreign folder. The user picks a local location (anywhere except inside their default download folder); the materialize engine continuously syncs the owner's drive to that location. Read-only on the mirror's side.
  • · Read-only is enforced by UI only in v1 — a banner + lock icon. Edits will be silently reverted on next sync. A future improvement (M5+) will add an edit-detection toast and/or OS-level chmod -w to prevent data loss.
  • · Avatar attribution everywhere. Every folder card carries the owner's avatar prominently; default mirror paths include the owner's name to disambiguate on disk.
  • · Space mount is an enhancement, not a prerequisite. Mounting unlocks the folder layer and the default parent location; it does not change file sharing.
  • · No direction picker anywhere. Direction is implicit per role — owner pushes, mirror peer pulls.
  • · Initial-scan preview (screen 6) is one shared dialog template used in four flows: space mount on non-empty path, owned-folder creation, foreign-folder mirroring, owned-folder move.
  • · ShareView abstraction is the seam through which a future multi-writer substrate (UnionView) can plug in without rewriting publish/materialize/UI/IPC.
