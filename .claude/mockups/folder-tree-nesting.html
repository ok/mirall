Nested-folder display — three concepts

Today FolderView renders a shared folder's contents as a flat list of full relative paths (project/docs/2024/report.pdf) — no way to collapse a subfolder, no visual depth, and the list grows unmanageably long. Three established patterns, each recreated faithfully from the shipped UI in our own tokens. Grounding: .claude/tasks/folder-nesting-ux-research.md.

Pattern → best-fit (research synthesis)

Concept Model a11y build Best fit
1 · Collapsible tree All depth inline; recursive expand/collapse; folders-first; collapsed folders show a count·size summary row. Accordion of nested disclosure buttons over native rows — not role=tree (which is single-column & SR-fragile). Browsing / auditing the whole structure. Recommended default.
2 · Breadcrumb drill-down One folder level at a time; interactive breadcrumb trail; click a folder to descend. <nav> breadcrumb + flat list — lowest a11y risk. Deep trees, narrow space, known-item nav. Matches Drive / Dropbox / OneDrive.
3 · Grouped summary Flat-but-groupable; top-level folders are collapsible sections with rich summaries; deeper paths flattened to a chip; "Show N more". Accordion of disclosure section headers over native rows. Mixed / shallow trees where compressing long folders to scannable lines is the goal.
✗ Miller columns Column browser (macOS Finder). — Rejected: ~900px fits only 2–3 readable columns; 4 levels force horizontal scroll. Shown below for the record.

1 · Collapsible folder tree

recommended default

The full hierarchy in one scroll. Folders expand/collapse in place (chevron right = collapsed, down = expanded — our existing convention). Depth is shown by indentation + a one-tier surface step (folders sit on surface-container-low, files on -lowest), not 1px guide rails. A collapsed folder compresses its whole subtree into a single count·size summary row (Material expansion-panel / Outlook count-on-collapse pattern). Toolbar adds Collapse all + a filter for the hundreds-of-files case.

a11y: each folder header is a <button aria-expanded aria-controls> (the APG disclosure contract — Enter/Space toggles); file rows keep native semantics. Leaf rows reserve the chevron's width (the empty w-5 spacer) so file icons align under their folder's icon (Fluent guidance). Collapse-all is a labelled control; the filter input has an aria-label.

Rejected sub-alternative: persistent VS Code-style 1px indent guide rails — they fight our "depth via surface tiers, not lines" rule, and the research shows they're noise at 2–4 levels (VS Code itself defaults them to on-hover). Depth here is carried by indentation + the one-tier surface step instead.

2 · Breadcrumb drill-down

One folder level at a time — the Drive / Dropbox / OneDrive model. The main pane shows exactly one folder's contents; an interactive breadcrumb above gives the path back up (every segment clickable except the current one). Folders are rows you click to descend (trailing chevron_right = "go deeper"). Compact (one line of chrome), focused, and the lowest a11y risk — but it trades away cross-folder overview. a11y: breadcrumb is <nav aria-label="Breadcrumb"><ol> with aria-current="page" on the current segment and decorative aria-hidden separators (APG breadcrumb pattern — keyboard handling is "not applicable", just links). Folder rows are buttons with an explicit aria-label="Open folder …"; the up-one-level control is labelled. No roving tabindex or expand-state machine — the whole list is plain native rows.

Trade-off surfaced: for a folder only ~2 levels deep this adds navigation steps for little gain (Microsoft: skip breadcrumbs for 2 levels). Strongest when folders go 4+ deep or carry hundreds of entries per level.

3 · Grouped summary + progressive disclosure

Flat-but-groupable. Top-level folders become collapsible section headers carrying a rich summary (count · size · how many are on your device). Inside a section, files are listed flat — deeper nesting is flattened to a small path chip rather than recursive indentation — and a long folder ends in "Show N more" (progressive disclosure with strong information scent). A Grouped / Flat toggle flips the whole view. This compresses the most while keeping nesting shallow on screen.

a11y: each section header is a <button aria-expanded aria-controls> (disclosure); the Grouped / Flat control is a role=group SegmentedControl with aria-pressed; "Show N more" is a labelled button with strong information scent (the count + folder name), not a bare "…". Path chips are decorative text inside the row's accessible name.

Why flatten deeper levels: beyond the top-level grouping, recursive indentation buys little for shallow trees and risks the over-indentation NN/g warns about — a path chip keeps every file one click from view while still showing where it lives.

✗ Rejected — Miller columns (column view)

The macOS Finder column browser: one column per level, selecting in column N reveals column N+1. Kept here for the record. Rejected because our content column is ~900px: it fits only 2–3 readable columns before names truncate, so a 4-level folder forces horizontal scrolling — the documented failure mode — and it forfeits the sortable single-level list. Strong only for deep, comparison-heavy trees, which our 2–4 level shares are not.
