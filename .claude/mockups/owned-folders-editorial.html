Mirall · Design Plans · Edition 2026-05-18

A field guide · eight plates · folder shares in Mirall

Owned
folders.

A single writer per folder. A path the owner picks. A continuous push from disk to space, and a read-only mirror waiting on the other side — opt-in, attributed, and surprisingly quiet.

The plan introduces folder shares as a peer of today's loose-file sharing. No "space mount" ceremony precedes them; no separate Add folder button lives in the page chrome. The drop area — the same surface that accepts files today — becomes the single entry point.

What follows is the design in eight plates: the empty space, the inhabited space, the door, the confirmation, the mirror, the preview, the menus, and the folder browse view.

Marginalia

1

One button, not two.

File vs folder is OS-picker plumbing, not a user choice. The disambiguation lives in a small popover that appears only when needed.

2

Drag-and-drop never sees the menu.

Drop a file or a folder; the component routes by what arrived. The menu is reserved for the click path. Today's "folders not supported" toast retires.

Hover state is visual confirmation.

Border-secondary + surface-container-low + a verb-form release prompt naming the count and the kind.

"Same surface, same rhythm."

1

Owner attribution stays prominent.

The avatar appears three times: header chip, folder card, warning copy. Repetition is intentional.

VI

Plate six

Look before
you sync.

Before any bytes move, the engine counts them. Three cards — down, up, conflict — answer the question "what's about to happen?" in three glances. One template, three flows.

Marginalia

1

Three flows, one dialog.

Add owned folder · mirror foreign · move foreign mirror. Same template, different verbs.

2

Colour codes the action.

Info-blue for downloads, success-teal for clean destinations, warning-yellow for conflicts or read-only consequences.

3

File list is collapsed.

Show file list (5) expands on click. Most flows resolve from the cards alone; the per-file list is for the careful reader.

"Three glances, three decisions."

VII

Plate seven

Three menus,
three relationships.

Each menu is a small statement of role. The owner does little — open, delete — because sync is the engine's responsibility, not the user's. The browser does less. The mirror-holder does a bit more.

Mirall

Role 1 — Mine

You own this folder. Sync is automatic; location is immutable; only two actions remain.

Role 2 — Browse

Someone else owns this folder, and you haven't mirrored it yet. The list is read on demand.

Role 3 — Mirrored

Someone else owns this folder; you keep a read-only local copy. Pause, relocate, or unmount.

Fig. VII — Action counts as design statement. Two, two, four.

"Sync is the engine's responsibility, not the user's. The owner's menu has two items because that is all that's needed."

Colophon.

Design principles

  • § One entry point. Files and folders are added from the same drop area. No Add folder button in the page chrome.
  • § Sections appear with content. No "Folders shared" heading until at least one folder share exists in the space.
  • § Owner location is immutable. To relocate a share, delete it and add a new one. Sync is the engine's responsibility; location is the moment-of-creation contract.
  • § No defaults synthesized. The OS picker opens at home; Mirall does not pre-fill paths. The global Download folder is the only path the app configures.
  • § Direction is implicit. Owner pushes, mirror peer pulls. No direction picker, no two-way mode, no per-peer overrides.
