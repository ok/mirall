5 · Catching-up prompt FUTURE · M6 · SharedView only

SharedView's Autobase has a single canonical state. When a peer returns from offline with queued edits that conflict with what other peers did in the meantime, Autobase will linearize them — typically losing one side. Before that resolution lands silently, surface the divergence and let the user decide. In UnionView (M1–M5) this dialog is not used — foreign-file deletes in UnionView are handled by the suppressed-paths set instead, and own-contribution deletes propagate via tombstones with no user choice needed.

7 · Create folder dialog

Triggered by the "New folder" button in screen 2. Only available when the space is mounted (Model A prerequisite). Takes name + direction only — the on-disk location is computed as a subdirectory of the space mount. Three direction options: inherit the space default, or override with push-only or pull-only. Pinning a folder to a fixed direction regardless of future space-default changes is handled later in the per-folder settings, not at creation.

Reading the mockup

  • · Every file in a space belongs to a folder share. There is no "loose file" concept any more.
  • · Each space is created with one folder share called "Default folder" that starts unmounted — i.e. behaves like today: browse + on-demand download to Downloads.
  • · Model A — one mount per space, folders are subdirectories inside it. The space is mounted to a single OS folder; folder shares appear as subdirectories. Default folder lives at the root of the mount. One chokidar watcher per space, one Hyperdrive prefix per space — no nested mounts on disk, no watcher overlap.
  • · Mount direction is set at the space level (default for all folders) with per-folder overrides. New folders default to inheriting the space's default direction; the user can override at creation.
  • · The "New folder" button is only available once the space is mounted. Creating a folder (screen 7) takes name + direction only; the on-disk path is computed as a subdirectory of the space mount.
  • · Status pills inside file rows replace download buttons once a folder is mounted: ✓ in sync, ↻ syncing, ⚠ conflict. Click-to-download is only visible in browse mode.
  • · Conflicts (two peers writing the same path) materialize the newer file at the real name and the older one as … (from Bob).ext. Surfaced as a per-folder badge and a per-file warning.
  • · When a peer reconnects with files that others have already removed, we never silently resurrect them — screen 5 shows the explicit choice. This is the Nextcloud "deleted files keep coming back" failure class.
  • · The conflict inbox is the primary signal, not renamed files on disk. Field research on Syncthing and Dropbox shows that filesystem-only conflict surfaces become invisible litter; users need a forced-confrontation list view (screen 6).
  • · Two-way direction copy is honest about UnionView's federation model: your changes to your own files sync everywhere, but you can only remove what you added. Foreign-file deletes via Finder are suppressed locally — the file stays in the space for everyone else, but stays gone on your disk. The Dropbox-style "anything anyone deletes, everyone loses" wording is reserved for the future SharedView / Autobase substrate (M6).
