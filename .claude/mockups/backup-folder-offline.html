Backup folder offline — mockup

The Backup screen when its folder (a drive or network share) is unreachable: today's flicker, the steady fix, and an optional single place for the message. Baseline: origin/main @ e6f6f8b6.

Recreated from code reproduced from the shipped .tsx Proposed new built from existing primitives and design.md tokens a11y name / role / state intent

1 · Today — the error flickers

Recreated from code BackupSettings.tsx— unchanged code on origin/main. Each retry sets state: 'running', which hides the red line and the offline hint and turns the button into “Backing up…”; the failure brings them back. With an urgent change pending this repeats as fast as the folder check fails.
Toggles the screen between the error and the retry every 400 ms, like an unreachable share.

2 · Proposed (parts 1 + 2) — steady while it retries

Proposed new schedule-rules.js · BackupSettings.tsx— nothing new on screen; the change is that it holds still. A failed run waits before retrying (1 min, doubling up to the hourly interval, reset on success), and the red line shows whenever lastError is set, not only while state === 'error'. A retry only changes the button to “Backing up…”, at most every few minutes. The offline line under the folder becomes a Callout tone="warning" — design.md’s tone for “a condition that holds right now and limits what the reader can do”, the same box as the read-only note in the mirror dialog (MirrorFolderModal.tsx:146). The red line above stays for the failed run; part 3 removes it.
