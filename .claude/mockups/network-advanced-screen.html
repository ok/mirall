Advanced details as its own screen — mockup

Proposal for moving Show advanced details off the Network status page. Click the toggle to flip light/dark.

What's proposed vs. recreated

Proposed (the delta): the in-page disclosure at the bottom of Network status (advancedOpen + <AdvancedDetails/>) becomes a navigation row into a new screen, network-advanced. The row is the app's existing sub-page affordance — ActionRow with Tile + chevron_right — the same one Account → This device uses to reach Network status itself (design.md §Account → This device). The six sections on the new screen are unchanged: same Section / Field / MaskedField rows, same order, same copy.
Recreated from code (baseline truth): screens/NetworkStatusScreen.tsx (PageHeader, VerdictBanner, ConnectionSummary, AdvancedDetails, BootstrapList); components/network/StatusRows.tsx (label w-48, value text-accent, reveal + copy, positive = text-online); screens/DiagnosticsCard.tsx; screens/AccountScreen.tsx (ROW, Tile, RowBody). Strings are the real locales/en/common.json values; anything marked NEW is proposed copy.

1 · Network status — the bottom of the page, after the change

Answering "how do I get there?": the page keeps its narrative order — verdict → what to do → summary → relayed connections — and then ends with a Troubleshooting group of two rows. Both rows are "things you do when something is wrong and you are reporting it", which is exactly the pair that belongs together: save the file we ask for and read the raw values. Diagnostics stops being a card of toggles you must scroll past, and Advanced stops being a trapdoor that doubles the page height.

Troubleshooting

The page now fits without a trapdoor. Today the bottom of Network status is a full Diagnostics card (intro + two Toggle rows + two buttons + a status line) followed by a disclosure that, when opened, appends six sections and 23 rows below the fold — the scroll position stays where it was, so the thing you asked for opens off-screen. Two rows replace both.

Proposed copy (NEW): networkStatus.troubleshooting "Troubleshooting" · networkStatus.advancedRow "Advanced details" (replaces advancedToggle "Show advanced details" — a destination, not a verb) · diagnostics.rowDesc "Save a file describing how your network behaves". Reused verbatim: networkStatus.advancedHint "Address, NAT, DHT, counters" is already written as a row description and moves there unchanged; diagnostics.title "Diagnostics".

a11y: each row is a <button> with aria-label = the row label (so agent-desktop can target "Advanced details" by name/role), the tile and chevron are aria-hidden, and focus lands on the new screen's <h1> via headingRef — PageHeader already supports it. The aria-expanded state disappears with the disclosure, which is the point: nothing expands any more.

2 · The new screen — network-advanced

A peer screen to Network status, not a modal: same PageHeader, same max-w-2xl column, back arrow returns to Network status. The six sections are lifted out of AdvancedDetails unchanged — same order, same labels, same masking and copy controls — so this is a move, not a redesign. Nothing is added except the title, the one-line intro, and the Copy all button, which is the action people actually take on this screen today by selecting six sections by hand.

Why "Copy all" and not a second diagnostics export: the file from Diagnostics is redacted and machine-readable; this is the six sections as text, for pasting into a chat with whoever is helping you. It is redacted by default, like the diagnostics bundle: the Public IP and the public key go in masked. The per-field CopyButton already copies the real value for the one case where you deliberately want it, so the bulk button never has to be the thing that leaks an address into a chat window. If that is too clever for one button, drop it — the screen is complete without it.

4 · Variant B — leave Diagnostics where it is

The minimum change: the Diagnostics card stays a card, and only the disclosure becomes a row. Pick this if you want the Save diagnostics button to stay one click away — support asks for that file often, and §1 puts it behind a tap. It is strictly smaller and ships without touching DiagnosticsCard.tsx. Cost: the page still ends with a full card of toggles, and the two "when something is wrong" tools stay visually unrelated.

Rejected: a modal, tabs across the top of Network status, a Settings → Advanced home, keeping the disclosure but auto-scrolling

A modal — this is a long scrolling read with reveal/copy affordances that you keep open while trying things elsewhere in the app. Modals in Mirall are for a decision (Modal is used for invite, remove, replace confirmations), and a modal traps focus and can't be reached by the back arrow.
Tabs on Network status ("Overview | Advanced") — the app has no tab primitive; the segmented control is an inline pattern used for filters, not for navigation. Adding a navigation tab set for one screen invents a primitive.
Hanging it off Settings → Network — that screen configures the network (limits, relays). These are live readings of the current connection, and they only make sense next to the verdict that sent you looking for them. It also strands the one entry point people actually arrive from, which is Account → Connection → Network status.
Keeping the disclosure and scrolling it into view — treats the symptom. The content is a second page's worth regardless, and the back button then means "leave Network status" when the user's mental back is "close the advanced stuff".

Wiring (for when this is built, §1 version): 'network-advanced' (and, for §1, 'network-diagnostics') join the Screen union in navigation.ts; ScreenRouter.tsx gains the matching cases with onBack={() => nav.setCurrentScreen('network-status')} — the never check at the bottom of the router means a missing case fails to compile. AdvancedDetails + BootstrapList move out of NetworkStatusScreen.tsx into screens/NetworkAdvancedScreen.tsx unchanged, and read the same useConnectionStatus() hook — the subscription lives in the app-wide ConnectionStatusProvider, so a second consumer costs nothing and the values are already live when the screen mounts. NetworkStatusScreen loses advancedOpen, formatBool and two imports.

Coverage this change owes (.claude/testing.md): renderer UI + a11y — a frontend scenario that opens Account → Connection → Advanced details, asserts the six section headings by role, and walks back; jsx-a11y clean; the new rows targetable by name/role from agent-desktop; a VoiceOver spot-check that focus lands on the new <h1>. No data-layer change, so no integration or flow test.
