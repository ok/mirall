Folder & file surface colors — harmonization

Today every card — spaces, folders (ShareCard), and files (FileCard) — is the identical surface-container-lowest card; only the glyph differs. The new folder tree (FolderBranch) broke this by putting folders on surface-container-low with a dark-mode hover that's invisible. This proposal harmonizes it into a consistent folders vs files two-tier system. Grounding: .claude/tasks/research-folder-file-color-harmonization.md. Toggle dark — the whole point is that both themes read correctly.

The neutral ramp (why dark is tricky)

The ramp is not monotonic by name in dark: -lowest (#21252b) is darker than the background, while -low/-highest/-high are progressively lighter. So "folders darker, files lighter than the background" maps to -lowest for folders and -low for files — in dark.

2 · Proposal A — two-tier, one hover

recommended

Folders = the canonical card (surface-container-lowest, unchanged from ShareCard). Files = one tier in (surface-container-low). Both hover to surface-container-highest — visible in both themes, never colliding with a resting tier or the icon tile (-high). The disclosure chevron becomes text-on-surface-variant. In dark: folder #21252b (darker than bg), file #2e3239 (lighter than bg) — as requested. Applied identically in both screens.

3 · Alternative A′ — no light-mode flip

optional

Option A folds folders onto -lowest, so in light mode folders read as the brightest (white) card and files as slightly recessed — the luminance relationship flips vs dark. If a fixed relationship is preferred (folders always darker than the background, files always lighter, in both themes), use theme-specific tokens: folder bg-surface-container dark:bg-surface-container-lowest, file bg-surface-container-lowest dark:bg-surface-container-low. Trade-off: the light-mode step is fainter.
