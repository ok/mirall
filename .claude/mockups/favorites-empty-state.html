What the copy claims, and where the code says so

  • Today: favorites take the first digits, then every other space (src/renderer/model/space-shortcut-order.js:1-3); activity never moves a digit. Proposed (state 4): favorites only.
  • ⌘1–9 / Ctrl+1–9 work from any screen on every platform: native View › Go to Space menu, src/main/menu.js:61-71.
  • Adding: the space header's More menu, SpaceHeaderBar.tsx:51-58; and the palette command “Add this space to Favorites”, only while in a joined space, useSpaceCommands.ts:31-37. It has no chord of its own (known-commands.ts).
  • All shortcuts: shortcuts.show = ⌘/ (known-commands.ts:32).
  • There is no favorites section on mirall.app to link to: DOCS_ANCHORS in shell/docs-links.js has none.

What favorites do

Pin the spaces you use most often for quick access. Each favorite gets its own keyboard shortcut.

  • Press ⌘1 to ⌘9 to jump to a favorite from anywhere in Mirall. Hover a card to see its number.
  • To add one, open a space and choose More › Add to Favorites. Or press ⌘K there and type “favorite”.

a11y The card stays DocsCard's <section aria-labelledby> with an <h3>. The three items are a <ul>; the first two are text (nothing to activate), so they sit outside the Tab order. Chords are <kbd> rendered through AcceleratorLabel, so VoiceOver reads them as text and Windows gets “Ctrl+1”.

a11y The third item is a real <button> named “See all keyboard shortcuts”, with aria-keyshortcuts="Meta+Slash" (Control+Slash off macOS). It runs the existing shortcuts.show command — no new dialog. It keeps DocsLink's row look but drops the open_in_new glyph, since it does not leave the app.

Proposed new The card’s description carries the main point, so the hint under “No favorites yet” goes: the current one (“Open a space and choose Add to Favorites from the menu…”) would repeat item 2, and a new one would repeat the card’s first sentence. The heading stays.

Rejected alternatives

Rejected DocsCard with three “learn more” links. Matches the screenshot exactly, but mirall.app has no favorites or shortcuts section, so every link would land on a generic page. The point of this card is the shortcuts, which fit in a sentence.

What favorites do

Favorites come first in your shortcuts.

  • → Keyboard shortcuts ↗
  • → Add a favorite ↗

Rejected An “Add to Favorites” button in the card. The tab has no space to act on, so the button would need a space picker. That's a new flow for a one-time step; the real control lives in the space's More menu, where the user already is when they want it.

Rejected Keycap always visible at the end of the row. Too prominent on a list people scan by name, and it widened every row. Numbering every space (favorites first, then the rest) was dropped with it: a number on a space you never pinned read as a mismatch.

Rejected A dedicated chord for favoriting (e.g. ⌘D). Out of scope for an empty state. The card would advertise a new shortcut, and every chord has to go through known-commands.ts and the cheatsheet invariant. Worth its own decision if wanted.

How it would be built

Proposed new DocsCard already owns the shell: icon tile, title, body, list, English note. The proposal gives it an items slot (ReactNode rows) alongside links, so this card and the share card stay one component. The English note shows only when the card has doc links, so it is absent here.

Proposed new New strings under spaces.*: emptyNoFavoritesHint removed, favoritesDocsTitle, favoritesDocsBody, favoritesTipJump, favoritesTipAdd; favoritesTipAllShortcuts reuses shortcuts.showShortcuts' meaning with its own wording. All five locales.

a11y Tests: the frontend scenario for the Favorites tab checks the card's heading, the three list items and that the button opens the cheatsheet; jsx-a11y covers the button name.
